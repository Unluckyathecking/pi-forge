# Governance

Pi Forge uses a maintainer-led governance model.

## Maintainers

The current project maintainer is
[@Unluckyathecking](https://github.com/Unluckyathecking). Maintainers triage
issues, review pull requests, make releases, and enforce the Code of Conduct
and security policy.

## Decisions

Routine changes are decided through issue and pull request discussion. Changes
to architecture, governance, security boundaries, or stable public APIs should
begin as an issue and include alternatives, compatibility impact, and a
migration path. Maintainers seek practical consensus and make the final call
when consensus is not possible.

## Becoming a maintainer

Sustained, constructive contributions may lead to an invitation to become a
maintainer. Signals include sound reviews, dependable issue triage, respect for
project boundaries, and consistent community conduct. Repository access is
granted incrementally and can be revoked for inactivity or violations of
project policy.

## Releases

Maintainers publish releases according to [CHANGELOG.md](CHANGELOG.md) and the
compatibility contract in [API_STABILITY.md](API_STABILITY.md). At least one
maintainer must review release-impacting changes.
